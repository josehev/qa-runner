1. Accessibility (WCAG 2.1 / 2.0 AA Compliance)

  • FAILKeyboard focus indicators — top navigation & Contact Us link
    How to test: Tab through all interactive elements; diff computed outline/box-shadow/border before vs. after focus. Criteria: every focusable element must show a visible focus indicator (WCAG 2.4.7).
    Repro: Load page → press Tab repeatedly to reach "Contact Us" or any top-nav button (Account & Billing, Services & Outages, Save Energy & Money, Clean Energy, Search, Log in or Register) → observe outline-style: none in both focused and unfocused states — no visible indicator at all.
  • FAILEscape key does not close "Log in or Register" panel
    How to test: Open a dismissible panel/modal via keyboard or click, then press Escape. Criteria: Escape should close dismissible UI (WCAG 2.1.2 — no keyboard trap / common expectation).
    Repro: Click "Log in or Register" → press Escape → aria-expanded stays "true", panel remains open. Clicking outside the panel also fails to close it; only re-clicking the toggle works.
  • FAILMissing <main> landmark
    How to test: Inspect DOM / accessibility tree for a <main> element or role="main". Criteria: page must expose exactly one main landmark so screen reader users can jump to primary content (WCAG 1.3.1 / 2.4.1).
    Repro: View page source — zero <main> tags and zero role="main" attributes. The "Skip to Main Content" link targets id="mainContent", which is a plain <div>, not a semantic landmark.
  • PASSImage alt text
    How to test: Inspect all <img> tags for non-null, descriptive alt attributes.
    All 13 images carry descriptive alt text (e.g., "An illustration of a piggy bank, checklist, and dollar symbol representing incentives and savings.").
  • PASSHeading hierarchy & landmark structure (header/nav/footer)
    Single <h1> confirmed ("Enroll Your Home Battery to Earn an Average of $180 per Summer"); logical H1→H2→H3 descent; <header>, two <nav>, and <footer> elements present.
  • FAILColor contrast — "Benefits of Enrolling" / "Get Started" card captions
    How to test: Sample computed color vs. background-color on rendered text; calculate WCAG contrast ratio. Criteria: ≥4.5:1 for normal text, ≥3:1 for large (18pt+/14pt bold+) text.
    Repro: Inspect "Get Incentives", "Improve Grid Reliability", "Reduce Emissions", and "Step 1: Check Eligibility" captions — color: rgb(89,89,89) on background: rgb(183,183,183), 18px non-bold. Measured ratio = 3.49:1, below the 4.5:1 requirement.
    All other sampled text (headings 14.35:1, body copy 14.35:1, error text 4.60:1, links 10.56:1) passes.
  • PARTIALForm field labeling & accessible error messaging
    How to test: Confirm every input has a programmatic label (<label>/aria-label); trigger a validation error and confirm it's announced via role="alert"/aria-live, not color alone.
    PASS: Search field has aria-label="search"; login modal fields (email, password, MFA code, remember-me) all have associated <label> elements.
    FAIL — error not announced: Open "Log in or Register" → enter test@test.com / wrongpassword123 → submit → error text appears ("Please call us at 1-877-434-4100...") inside a <div class="login login--oru..."></div> with no role="alert" or aria-live attribute — screen reader users are not notified.
