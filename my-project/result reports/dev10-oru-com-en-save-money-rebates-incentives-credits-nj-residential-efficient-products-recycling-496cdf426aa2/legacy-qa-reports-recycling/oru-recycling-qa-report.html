1. Accessibility (WCAG 2.1 / 2.0 AA)

  • Keyboard reachability of all interactive elements PASS
    How to test: Tab sequentially through the page; every interactive control should receive focus in DOM order.
    Result: Header, FAQ, cards, and footer links all reachable in a 15+ element tab sweep.
  • Visible focus indicator on every focusable element FAIL
    Criteria: WCAG 2.4.7 — focused element must have a visible outline/highlight.
    Evidence: The 5 FAQ accordion buttons compute to outline-style:none; outline-width:0; box-shadow:none on focus. Repro: Tab to any FAQ question (e.g. "Do I need to own the appliance?") → no visible ring appears, though focus has moved (confirmed via computed style, not just visual inspection). Nav/footer links by contrast correctly show a 2px outline.
  • Logical tab order / no keyboard traps PASS
  • Skip-to-content link present and functional PASS
    "Skip to Main Content" is the first focusable element and moves focus to #mainContent.
  • Alt text present on all images PASS
    All 10 <img> elements carry non-empty, descriptive alt text.
  • ARIA landmarks (header/nav/main/footer) FAIL
    Criteria: page should expose header, nav, main, footer landmarks for AT users.
    Evidence: <header>, <nav>(×2), <footer> exist, but there is no <main> element or role="main" anywhere. The content wrapper is a plain <div id="mainContent">.
  • Heading hierarchy is logical (no skipped levels) FAIL
    Hidden login-modal markup injects H4(empty)→H3("Verify Your Identity")→H5("To protect your account...") ahead of the visible H1 ("Get Rewarded for Recycling") in DOM order — confuses screen-reader heading navigation even though visually hidden. Visible content hierarchy itself (H1→H2→H3) is correct.
  • Icon-only buttons have accessible names PASS
    Login/search/menu-toggle icon buttons all carry descriptive aria-label values.
  • Form field labeling PARTIAL
    Header search input relies on aria-label (acceptable). Hidden login-modal email/password fields have proper <label for> association. A hidden MFA field's full accessible-name behavior could not be fully exercised without live credentials.
  • Accessible error messaging on form submission NOT TESTED
    No submittable form could be driven to a failure state without live credentials/backend state in this environment.
  • Color contrast ratios (4.5:1 text / 3:1 large text) PASS
    Measured computed color/background pairs: body text #2A2A2A on white = 14.35:1; CTA white-on-teal = 10.56:1; footer links = 11.50:1; FAQ text = 14.35:1; orange anchor-tab text (teal on #FF8E2C) = 4.60:1 — passes but close to the 4.5:1 floor; recommend monitoring if this palette changes.
